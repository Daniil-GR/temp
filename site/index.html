001 / NETWORKINGDOMAIN NAME SYSTEM↑ Back to library

What happens during a DNS lookup?

A domain name is a human-friendly label. DNS provides records that help software find services associated with that label.

When you open a website, the browser or operating system typically asks a recursive resolver for the relevant records. The resolver may already have a cached answer. Otherwise it follows the DNS delegation chain until it can obtain an authoritative answer. The browser can then try to connect to one of the returned addresses.

A records carry IPv4 addresses, AAAA records carry IPv6 addresses, and CNAME records point one DNS name to another. A DNS answer does not prove a web server is running: resolution and connectivity are different checks.

IMPORTANT DISTINCTION

TTL is a cache lifetime for DNS records, not a promise that an address will become reachable or change everywhere at the exact same moment.

Inspect a DNS A record
dig example.com A +short

Further reading: DNS fundamentals and RFC 1035.

002 / SECURITYENCRYPTED TRANSPORT↑ Back to library

Why HTTPS needs certificates

HTTPS is HTTP transported over a protected connection, normally using TLS. TLS aims to authenticate the peer and protect data in transit.

During connection setup, a browser and server negotiate how to communicate securely. The server generally presents a certificate chain. The browser checks factors including the hostname, validity period and whether the chain leads to a trusted authority.

The URL's hostname matters: a certificate for a different domain does not automatically validate a new subdomain. Encryption also does not mean the website itself is trustworthy; it means the connection has specific cryptographic protections.

Inspect a site's response and certificate validation
curl -Ivs https://example.com/

Further reading: MDN: TLS and TLS 1.3 specification.

003 / PERFORMANCEHTTP CACHING↑ Back to library

Fresh content, fewer requests

A cache can reuse a previously received response. Whether it may do so depends on the response's caching rules and context.

Cache-Control: max-age=600 permits a response to be considered fresh for up to ten minutes, subject to other directives and the cache's behavior. Once stale, a cache may be able to revalidate using an ETag and an If-None-Match request header.

A 304 Not Modified response allows reuse of the stored representation. no-cache requires successful validation before reuse; no-store instructs compliant caches not to store the response. These two directives are not synonyms.

Read caching headers
curl -I https://example.com/

Further reading: MDN: HTTP caching.

The meaning behind a status code

A web response contains a status code, headers and sometimes a response body. The status code is a starting point, not a full diagnosis.

200OK — the request succeeded.
301Moved Permanently — the resource has a new permanent URL.
404Not Found — the requested resource was not found.
429Too Many Requests — the sender is rate-limited.
502Bad Gateway — a gateway received an invalid upstream response.
503Service Unavailable — the server cannot currently handle the request.

For diagnosis, inspect the requested URL, response headers, intermediate proxies and application logs. A 502 alone cannot identify whether the underlying cause is a failed origin, a timeout or something else.

Display the status and response headers
curl -sS -D - -o /dev/null https://example.com/

Further reading: MDN: HTTP status codes.
